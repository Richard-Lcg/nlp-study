# MinerU vs pdfplumber 完整对比

## 一、核心差异总览

| 对比维度      | 传统库 pdfplumber                      | AI 解析引擎 MinerU                             |
|:--------- |:----------------------------------- |:------------------------------------------ |
| **解析方式**  | 基于规则的文本流解析，依赖 `pdfminer.six` 引擎     | **AI 视觉语言模型驱动**，VLM + Pipeline 双引擎         |
| **核心优势**  | 轻量级、易用，适合**机器生成、版式规整**的 PDF         | 高质量、结构化输出（Markdown/JSON），处理复杂文档能力极强        |
| **扫描件支持** | ❌ 不支持（无法处理图片型或扫描版 PDF）              | ✅ 原生支持，通过 OCR 识别多达 109 种语言                 |
| **表格解析**  | 基于线框和文本位置检测，复杂表格（无边框、合并单元格）易丢失列     | **结构级还原**，输出完整 HTML 结构，合并单元格准确率高           |
| **数学公式**  | 无法有效识别，通常丢弃或保留为乱码                   | 自动识别并转换为可编译的 **LaTeX 格式**                  |
| **排版顺序**  | **物理顺序输出**。多栏排版时内容错乱（如左栏第一行后接右栏第一行） | **按阅读顺序重排**，正确识别学术论文、杂志等复杂版式的逻辑顺序          |
| **输出格式**  | 纯文本，需二次处理才能获得结构信息                   | 结构化 **Markdown** 或元素级 **JSON**，天然保留文档层级和语义 |
| **环境与性能** | 轻量级，依赖少                             | 本地部署较重（建议 GPU），但可通过云端服务免去环境配置              |
| **工作原理**  | 专注于**字符、线条和矩形**级别的信息提取              | 致力于**理解整页布局和语义**——“读懂”而非“读取”               |

## 二、详细对比说明

### 1. 解析方式与原理

- **pdfplumber**：基于 `pdfminer.six`，通过解析 PDF 文件内部的字符、线条、矩形坐标来重建文本和表格。本质是规则匹配。
- **MinerU**：采用视觉语言模型（VLM）识别页面元素，再通过 Pipeline 进行结构化重组。能像人眼一样“看”懂页面布局。

### 2. 扫描件与图片型 PDF

- **pdfplumber**：无法解析扫描件，因为其依赖文本层。若 PDF 无文本层，输出为空。
- **MinerU**：内置 OCR 引擎，支持 109 种语言，可完整识别扫描版 PDF 并输出带布局的 Markdown。

### 3. 表格解析能力

- **pdfplumber**：能提取有明确边框的表格，但对于**无边框表格**、**合并单元格**、**跨页表格**、**嵌套表格**常常解析失败，导致行列错位或数据丢失。
- **MinerU**：能还原表格的完整 HTML 结构（`<table>`, `<tr>`, `<td>` 等），正确识别合并单元格（`rowspan`/`colspan`），支持无线框表格和嵌套表格。

### 4. 数学公式

- **pdfplumber**：公式会被拆解为独立的字符或符号，无法识别整体结构，输出通常是乱码或缺失。
- **MinerU**：自动识别行内公式和行间公式，并转换为标准 LaTeX 代码（如 `$E=mc^2$` 或 `\begin{equation}...\end{equation}`），可直接用于渲染或复制到 Overleaf。

### 5. 排版顺序与多栏文档

- **pdfplumber**：按 PDF 内部对象存储顺序（物理顺序）输出。对于两栏或三栏的学术论文，输出结果通常是：左栏第一行 → 右栏第一行 → 左栏第二行 → 右栏第二行……完全打乱语义。
- **MinerU**：通过布局分析（Layout Analysis）识别栏区域，按人类阅读顺序（从左到右、从上到下，跨栏）重新排列内容，保证段落和句子的逻辑连贯性。

### 6. 输出格式与应用

- **pdfplumber**：输出纯文本字符串。若需获得标题、段落、表格等结构化信息，必须自行编写大量解析和规则代码。
- **MinerU**：可直接输出 **Markdown**（标题、列表、代码块、表格、公式均保留）或 **JSON**（元素级精细控制，包含坐标、类型、内容等）。非常适合直接喂给 RAG 系统或大语言模型。

### 7. 部署与性能

- **pdfplumber**：纯 Python 库，无额外依赖，CPU 运行，速度快。适合轻量级脚本和服务。
- **MinerU**：
  - 本地部署需要 GPU（推荐 8GB+ 显存），模型权重约 2-4 GB，适合高隐私要求场景。
  - 云端服务（SDK/CLI）提供免费 Flash 模式（单文件 10MB/20页内），无需显卡，即开即用。

## 三、场景选型建议

| 你的文档特征                    | 选择 pdfplumber | 选择 MinerU       |
|:------------------------- |:-------------:|:---------------:|
| 机器生成的纯文本 PDF（无扫描、无复杂表格）   | ✅ 推荐          | ⚠️ 可选（但功能过剩）    |
| 扫描件 / 图片型 PDF             | ❌ 不可用         | ✅ 推荐            |
| 包含无边框表格、合并单元格、跨页表格        | ❌ 效果差         | ✅ 推荐            |
| 包含数学公式（论文、教材）             | ❌ 不可用         | ✅ 推荐            |
| 多栏排版（如学术论文、杂志）            | ❌ 输出错乱        | ✅ 推荐            |
| 需要直接获取结构化 Markdown / JSON | ❌ 需自己写解析      | ✅ 直接输出          |
| 部署环境简陋（无 GPU、低内存）         | ✅ 合适          | ⚠️ 需使用云端 API    |
| 数据隐私要求极高（禁止外传）            | ✅ 可纯本地        | ✅ 本地部署模型（需 GPU） |

## 四、总结

**最终选择：如果文档只有文字和简单表格，选 pdfplumber；否则，无脑选 MinerU（尤其是云端免费版）。**
