# DeepSeek-V3 与 DeepSeek-V2 的主要区别

基于 DeepSeek-V3 技术报告，以下是与 V2 相比的关键差异和改进：

## 1. 架构改进

| 方面                 | DeepSeek-V2                  | DeepSeek-V3                                                                       |
| ------------------ | ---------------------------- | --------------------------------------------------------------------------------- |
| **负载均衡策略**         | 采用辅助损失（auxiliary loss）强制负载均衡 | **首创无辅助损失策略**（auxiliary-loss-free），通过动态调整每个专家的偏置项（bias term）实现负载平衡，避免性能损失         |
| **多 token 预测**     | 无                            | **引入多 token 预测（MTP）** 训练目标，每个 token 额外预测 1 个未来 token（深度 D=1），提升模型性能和推理加速（可配合推测解码） |
| **MoE 门控函数**       | 使用 softmax 计算亲和度             | 改用 **sigmoid 函数**计算亲和度，然后对选中的 top-K 亲和度进行归一化得到门控值                                 |
| **总参数/激活参数**       | 236B / 21B                   | **671B / 37B**（规模大幅扩大）                                                            |
| **MoE 配置**         | 1 个共享专家 + 160 个路由专家，激活 6 个   | **1 个共享专家 + 256 个路由专家，激活 8 个**（细粒度更高）                                             |
| **Transformer 层数** | 60 层（V2 为 60）                | **61 层**                                                                          |
| **隐藏维度**           | 5120（V2）                     | **7168**                                                                          |
| **注意力头数**          | 128 头，每头 128 维               | 相同，但 KV 压缩维度 d_c=512（V2 可能是 512？），查询压缩维度 d_c'=1536                                |

## 2. 训练效率与成本

| 指标               | DeepSeek-V2            | DeepSeek-V3                                                                |
| ---------------- | ---------------------- | -------------------------------------------------------------------------- |
| **FP8 训练**       | 未使用（使用 BF16）           | **首次在超大规模模型上验证 FP8 混合精度训练**，大幅降低显存和通信开销                                    |
| **训练框架**         | 基础流水线并行                | **DualPipe 算法**：双向流水线调度，实现计算与通信完全重叠，显著减少流水线气泡                              |
| **跨节点通信**        | 标准 all-to-all          | 定制化内核，利用 NVLink（160GB/s）和 InfiniBand（50GB/s）带宽差异，限制每个 token 最多发往 4 个节点     |
| **训练成本**         | 未明确（V2 约 4.2M GPU 小时？） | **2.788M H800 GPU 小时**（预训练 2.664M + 上下文扩展 119K + 后训练 5K），按 2/GPU小时计仅5.576M |
| **每万亿 token 成本** | 较高                     | **仅 180K H800 GPU 小时**（约 3.7 天在 2048 卡集群上）                                 |
| **预训练 token 数**  | 8.1T（V2）               | **14.8T**（更多数学、编程、多语言数据）                                                   |

## 3. 上下文长度

| 阶段          | DeepSeek-V2    | DeepSeek-V3            |
| ----------- | -------------- | ---------------------- |
| **预训练最大长度** | 4K             | 4K（相同）                 |
| **扩展后长度**   | 128K（YaRN 两阶段） | **128K**（相同方法，但训练更稳定）  |
| **NIAH 测试** | 表现良好           | **128K 内全窗口表现优异**（图 8） |

## 4. 后训练创新

| 方面                      | DeepSeek-V2 | DeepSeek-V3                                                                  |
| ----------------------- | ----------- | ---------------------------------------------------------------------------- |
| **推理能力蒸馏**              | 无           | **从 DeepSeek-R1 系列蒸馏长链推理（Long CoT）能力**，显著提升数学和代码性能（如 MATH-500 从 74.6 → 83.2） |
| **自奖励（Self-Rewarding）** | 无           | 使用 **DeepSeek-V3 自身的投票评估作为反馈源**（Constitutional AI 方法）                        |
| **数据构造**                | 常规 SFT      | 针对推理数据采用 **R1 蒸馏 + 专家模型生成**，非推理数据使用 V2.5 + 人工验证                              |

## 5. 推理部署

| 方面        | DeepSeek-V2 | DeepSeek-V3                                                              |
| --------- | ----------- | ------------------------------------------------------------------------ |
| **预填充阶段** | 未详细说明       | 最小部署单元 **4 节点 32 GPU**，使用 TP4+SP+DP8，MoE 部分 EP32，引入 **冗余专家**（32 个）实现负载均衡 |
| **解码阶段**  | 未详细说明       | 最小部署单元 **40 节点 320 GPU**，每个 GPU 仅托管 1 个专家 + 冗余专家，使用 **IBGDA** 降低延迟       |
| **推测解码**  | 无           | 可复用 **MTP 模块**进行推测解码，第二 token 接受率达 **85%~90%**，生成速度提升 **1.8 倍 TPS**      |

## 6. 硬件设计建议

V3 首次基于实际训练经验向硬件厂商提出系统建议，V2 未涉及：

- **通信硬件**：希望未来芯片将通信任务从 SM 卸载到专用协处理器，统一 IB 和 NVLink 接口

- **计算硬件**：Tensor Core 支持更高累积精度、支持 tile/block 级量化、支持在线量化、支持转置 GEMM

## 7. 评估表现

| 基准                  | DeepSeek-V2 | DeepSeek-V3                      |
| ------------------- | ----------- | -------------------------------- |
| MMLU                | ~80.6       | **88.5**（接近 GPT-4o 和 Claude-3.5） |
| MMLU-Pro            | ~66.2       | **75.9**                         |
| GPQA-Diamond        | ~35.3       | **49.9**（仅次 Claude-3.5）          |
| MATH-500            | ~74.6       | **83.2**（超越 o1-preview）          |
| HumanEval-Mul       | ~77.4       | **80.5**                         |
| LiveCodeBench (CoT) | ~29.2       | **33.4**                         |

## 总结

DeepSeek-V3 在 V2 的高效架构（MLA + DeepSeekMoE）基础上，通过 **无辅助损失负载均衡** 和 **多 token 预测** 两项核心创新，结合 **FP8 训练**、**DualPipe** 等工程优化，显著提升了模型性能（尤其在代码和数学领域），同时大幅降低了训练成本。后训练阶段通过 **R1 蒸馏** 进一步增强了推理能力，使 V3 成为当时最强的开源模型，性能比肩闭源前沿模型。
